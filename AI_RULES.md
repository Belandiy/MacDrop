# AI Rules & Architectural Memory for MacDrop

## 1. Архитектура интернационализации (i18n)
- **Запрет inline-тернарников**: Никогда не использовать конструкции вида `{lang === 'en' ? 'History' : 'История'}` в JSX/TSX коде компонентов и экранов. Это антипаттерн, ломающийся при добавлении 3+ языков.
- **Единая схема локализации (`LocaleSchema`)**: Все строки должны быть строго структурированы по доменным секциям (`nav`, `window`, `status`, `dropzone`, `transfers`, `devices`, `history`, `folder`, `settings`, `updates`, `logs`, `pairing`, `airbridge`) в файле `src/renderer/src/i18n/locales/ru.ts`.
- **Строгая типизация переводов**: Любой новый язык (`en.ts`, `de.ts`, `zh.ts`) обязан типизироваться как `LocaleSchema = typeof ru`. TypeScript компилятор (`tsc --noEmit`) гарантирует 100% соответствие ключей и типов между всеми языками.
- **Хук `useTranslation`**: Все UI-компоненты получают переводы исключительно через `const { t } = useTranslation()`.
  - Поддерживается dot-нотация (`t('settings.targetFolder')`), короткий поиск и интерполяция параметров (`t('transfers.allFilesTransferred', { count: 5 })`).
  - Fallback-стратегия: при отсутствии ключа в текущем языке автоматически возвращается значение из словаря `ru`.
- **Совместимость с модульными тестами (Vitest)**: Значение по умолчанию в `defaultContextValue` контекста всегда настроено на русский язык (`ru`), поэтому изолированные тесты компонентов (render без `<LanguageProvider>`) продолжают успешно проходить без переписывания тестовых фикстур.

## 2. Дизайны и кастомные стили (`src/renderer/src/designs/`)
- Все варианты оформления (`classic-native`, `studio-titanium`, `default`) равноправны, должны использовать хук `useTranslation()` и поддерживать мгновенную смену языка интерфейса без перезагрузки приложения.
